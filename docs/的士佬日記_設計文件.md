### 全遊戲統一慣例

所有關卡、程式及答案都必須跟從以下慣例，避免學生混淆。

- 陣列由索引 0 開始，容量一律為 5（索引 0–4）。
- 堆疊：`top = -1` 代表空堆疊；`top == 4` 代表已滿。
- 兩種隊列都用 `count` 記錄項目數量：`count == 0` 代表空，`count == 5` 代表已滿。
- 環形隊列：`head` 指向隊頭項目；`tail` 指向下一個空位；移動時用 `% 5`。
- 鏈表：`data[]` 存資料，`nxt[]` 存下一個節點的索引；`-1` 代表「冇下一個」（終點）。用 `nxt` 而不是 `next`，因為 `next` 是 Python 內置名稱。
- 程式用 `global` 修改指標變量（遊戲在第一章解釋一次）。

考試模式另設一題「`tail` 指向最後一個項目」的版本，讓中六學生遇到不同寫法時不會慌。

## 第一章　車尾箱（堆疊 Stack）

本章重點：後進先出 (LIFO)、`top` 的移動次序、空／滿檢查，以及「pop 後資料仍留在陣列」。車尾箱只放得一行 5 袋行李，最後放入的一袋必須最先拎出。

### 重溫畫面

- 堆疊 (Stack)：只可以在頂部加入 (push) 或取出 (pop) 項目，即後進先出 (LIFO, Last In First Out)。
- `top` 記錄頂部項目的索引；`top = -1` 代表空堆疊；容量為 5 時，`top == 4` 代表已滿。
- push：先 `top + 1`，再放入資料。pop：先取出資料，再 `top - 1`。
- `global top`：在函式內修改函式外的變量時要寫，否則 Python 會當 `top` 是另一個新變量。

本章程式：

```python
trunk = [None] * 5
top = -1

def push(x):
    global top
    if top == 4:
        print("車尾箱已滿")
    else:
        top = top + 1
        trunk[top] = x

def pop():
    global top
    if top == -1:
        print("車尾箱冇嘢")
        return None
    else:
        x = trunk[top]
        top = top - 1
        return x
```

介面：車尾箱畫成直向 5 格，索引 0 在最底；右邊一個箭嘴標示 `top`。不在堆疊內但仍存在陣列的資料以灰色顯示。

### 1-1　阿婆上車（操作）

- 對白：阿婆「後生仔，幫我放三袋嘢入車尾箱呀。」發哥「記住，先郁 top，再放嘢！」
- 開始：`trunk = [None]*5`，`top = -1`。
- 任務：依次執行 `push("紅")`、`push("藍")`、`push("橙")`。每次先按 `top` 的 +，再點格放入。
- 答案：`trunk = [紅, 藍, 橙, None, None]`，`top = 2`。
- 錯誤處理：未按 + 就放入 → 發哥讀出當時 `top` 的數值，例如「你放落 `trunk[top]`，而家 `top` 係 0，即係 `trunk[0]`，會壓扁咗紅袋！先郁 top 啲！」（第一袋 `top = -1` 時補充：Python 的 `trunk[-1]` 是最後一格，不是最底）放錯格 → 「放嘅位置一定係 `trunk[top]`。」
- 提示：「空車尾箱 top 係 -1，+1 就係 0，即係最底嘅格。」

### 1-2　阿婆落車（預測）

- 對白：阿婆「我到喂，幫我拎兩袋出嚟就得。」
- 開始：`[紅, 藍, 橙, None, None]`，`top = 2`。執行 `pop()` 兩次。
- Q1 第一次 `pop()` 傳回什麼？選項：橙 ✔ ／ 紅（回饋：「紅袋最先入，壓底呀。」）／ None
- Q2 兩次 `pop()` 後 `top` 是多少？選項：0 ✔ ／ 1 ／ -1 ／ 2
- Q3 `trunk[2]` 現在是什麼？選項：橙 ✔ ／ None ／ 藍
- Q3 解釋：pop 只是移動 `top`，沒有刪除陣列內的資料；橙仍在陣列，但已不屬於堆疊（介面轉為灰色）。選 None 的回饋：「程式邊一行將佢設做 None？睇清楚 pop() 啲。」

### 1-3　最底嗰袋（預測）

- 對白：趕飛機太太「我要紅色嗰袋，快啲！」發哥「佢嗰袋壓底喇……」
- 開始：`[紅, 藍, 橙, 黃, None]`，`top = 3`。
- Q1 要執行多少次 `pop()` 才取得紅？選項：4 ✔ ／ 3（回饋：「3 次之後紅袋仍然喺車尾箱，要再 pop 一次先拎到。」）／ 1

### 1-4　塞爆車尾箱（填空）

- 對白：發哥「個車尾箱得 5 格，第 6 袋放唔落就要講啲乘客知，唔好硬塞！」

## 第二章　的士站（隊列 Queue：移位版）

本章重點：先進先出 (FIFO)、`count` 的用法，以及「每次離隊都要把全部項目向前移」的代價——這是第三章的伏筆。的士站有 5 個車位，車位 0 是最前；頭架車載客離開後，後面每架車都要向前移一格。

### 重溫畫面

- 隊列 (Queue)：在隊尾加入 (enqueue, enq)，在隊頭取出 (dequeue, deq)，即先進先出 (FIFO, First In First Out)。
- 移位版：隊頭永遠在 `rank[0]`；`count` 記錄有多少個項目，新項目放在 `rank[count]`。
- `count == 0` 代表空，`count == 5` 代表已滿。
- deq 後要把 `rank[1]` 至 `rank[count-1]` 逐一向前移一格。

本章程式：

```python
rank = [None] * 5
count = 0

def enq(x):
    global count
    if count == 5:
        print("的士站已滿")
    else:
        rank[count] = x
        count = count + 1

def deq():
    global count
    if count == 0:
        print("的士站冇車")
        return None
    x = rank[0]
    for i in range(count - 1):
        rank[i] = rank[i + 1]
    count = count - 1
    return x
```

介面：橫向 5 個車位，車位 0 在左（近上客位置）；每架車寫司機花名（阿強、阿明、肥仔、阿May、豪哥）。每移一架車，右上角「移動次數」加 1，並顯示一縷黑煙（燒油）。

### 2-1　排隊等客（操作）

- 對白：發哥「入的士站要排隊，唔好打尖！新嚟嘅車排最尾。」
- 開始：全空，`count = 0`。
- 任務：依次執行 `enq("阿強")`、`enq("阿明")`、`enq("肥仔")`。每次先點格放車，再按 `count` 的 +。
- 答案：`[阿強, 阿明, 肥仔, None, None]`，`count = 3`。
- 錯誤處理：放錯格 →「新車要放喺 `rank[count]`，`count` 而家係幾多？」
- 提示：「`count` 同時話你知有幾多架車，同埋下一個空位喺邊。」

### 2-2　頭架車走（預測）

- Q2 執行後 `rank` 是？選項：`[阿明, 肥仔, 肥仔, None, None]` ✔ ／ `[阿明, 肥仔, None, None, None]` ／ `[None, 阿明, 肥仔, None, None]`
- Q2 解釋：迴圈只是「複製」到前一格，沒有清除最後一格；`rank[2]` 的肥仔是舊資料，因為 `count` 已是 2，它不算在隊列內（灰色顯示）。
- Q3 `count` 是多少？選項：2 ✔ ／ 3 ／ 1
- Q4 迴圈內 `rank[i] = rank[i + 1]` 執行了多少次？選項：2 ✔ ／ 3 ／ 1

### 2-3　郁到攰（預測）

- 對白：發哥「五架車排滿，前面走一架，後面四架都要郁……好嘥油！」
- 開始：`[A, B, C, D, E]`，`count = 5`。

- Q3 如果的士站有 100 個車位而且排滿，一次 `deq()` 要移動多少次？選項：99 ✔ ／ 100 ／ 1

### 2-4　填空

- Q2 最後 `rank` 及 `count`？答案：`[C, D, D, None, None]`，`count = 2`。干擾項：`[C, D, None, None, None]`、`[None, None, C, D, None]`。

### 收工小測

## 第三章　的士站改革（環形隊列 Circular Queue）

本章重點：只移動指標、不移動資料；`% 5` 令指標由 4 回到 0；`head == tail` 可以代表空，也可以代表滿，所以要靠 `count` 判斷。發哥提議：「做咩要全部車郁？郁個『下一架』牌咪得囉！」

### 重溫畫面

- 環形隊列 (Circular Queue)：資料留在原位，只移動 `head`（隊頭）及 `tail`（下一個空位）。
- 指標到達最後一格後回到第一格：`tail = (tail + 1) % 5`。
- 模除 (%)：求餘數，例如 `5 % 5 = 0`、`3 % 5 = 3`。
- `count == 0` 代表空，`count == 5` 代表已滿；單靠 `head == tail` 分不出是空還是滿。
- 環形只是想像出來的；記憶體內仍然是一行普通陣列。

本章程式：

```python
bay = [None] * 5
head = 0      # 下一架車 (front)
tail = 0      # 下一個空位 (next empty bay)
count = 0     # 有幾多架車

def enq(x):
    global tail, count
    if count == 5:
        print("的士站已滿")
    else:
        bay[tail] = x
        tail = (tail + 1) % 5
        count = count + 1

def deq():
    global head, count
    if count == 0:
        print("的士站冇車")
        return None
    x = bay[head]
    head = (head + 1) % 5
    count = count - 1
    return x
```

介面：上方是環形圖（5 個車位圍成一圈，「下一架」牌指著 `head`，「空位」牌指著 `tail`）；下方是真正的一行陣列。兩者同一格同時亮起。指標由 4 跳到 0 時播放「兜返個圈」動畫。

### 3-1　發哥改革（概念）

- 對白：發哥「上次郁車郁到我腰都痛！今次架架車企定唔郁，郁個牌就得。」
- Q1 用環形隊列，`deq()` 時要移動多少架車？選項：0 ✔ ／ 4 ／ 視乎有多少架車
- Q2 以下哪一項正確？選項：環形隊列在記憶體內仍然是一行普通陣列 ✔ ／ 電腦真的把記憶體排成一個圓形（回饋：「個圈只係方便我哋諗，記憶體入面都係 0 至 4 一行。」）
- Q3 `(4 + 1) % 5` 等於多少？選項：0 ✔ ／ 5 ／ 1

### 3-2　新制度開工（操作）

- 開始：全空，`head = 0`、`tail = 0`、`count = 0`。
- 任務：依次 `enq("阿強")`、`enq("阿明")`、`enq("肥仔")`。每次：點 `bay[tail]` 放車 → 按 `tail` 的 + → 按 `count` 的 +。
- 答案：`[阿強, 阿明, 肥仔, None, None]`，`head = 0`、`tail = 3`、`count = 3`。
- 錯誤處理：先郁 `tail` 再放車 →「咁樣第一格會空咗，車泊錯位喇！」

### 3-3　車走，牌郁（預測）

- Q1 兩次 `deq()` 的輸出？選項：阿強、阿明 ✔ ／ 肥仔、阿明
- Q2 執行後 `head`、`tail`、`count`？選項：2、3、1 ✔ ／ 0、1、1（回饋：「架車冇郁，郁嘅係 head。」）／ 2、1、1
- Q3 `bay` 是否有改變？選項：沒有，`[阿強, 阿明, 肥仔, None, None]` ✔ ／ 變成 `[肥仔, None, None, None, None]`
- 解釋：阿強及阿明仍在陣列內（灰色），但已不在隊列內。

### 3-4　兜返個圈（填空 + 排列）

- 填空 Q1 `tail = ____` 選項：`(tail + 1) % 5` ✔ ／ `tail + 1`（回饋：「去到 5 就爆，冇車位 5 㗎！」）／ `(tail % 5) + 1`（回饋：「`tail = 4` 時會變 5，一樣超出範圍。」）／ `(tail + 1) % 4`（回饋：「咁樣車位 4 永遠用唔到。」）

- Q5 又是 `head == tail`，今次是？答案：空。發哥：「頭先都係 head 等於 tail，所以一定要有 `count`！」
- 捉錯：`deq` 寫成 `head = head + 1`。點出錯的一行並改正。追問：這個錯誤何時才出現？選項：`head` 由 4 再加 1 時 ✔ ／ 第一次 `deq` 時。

## 第四章　順路經…（鏈表 Linked List）

本章重點：資料在陣列內的次序不等於鏈表的次序；跟著 `nxt` 走；插入時要先接好新節點，再改舊節點；刪除只需改一個指標。乘客大學生阿 Ken 不停加站、改站，玩家要用鏈表記住路線。

### 重溫畫面

- 鏈表 (Linked List)：每個節點 (Node) 有資料及指向下一個節點的指標 (Pointer)。
- 以陣列表示：`data[i]` 存資料，`nxt[i]` 存下一個節點的索引；`head` 是第一個節點的索引。
- `nxt[i] = -1` 代表這是最後一個節點。
- 插入及刪除不用移動其他資料，只需改指標；但要找第 n 個節點，必須由 `head` 開始逐個走（不可直接跳去）。

本章程式：

```python
data = [None] * 5
nxt = [None] * 5
head = -1

def insert_after(p, new, stop):
    data[new] = stop
    nxt[new] = nxt[p]
    nxt[p] = new

def delete_after(p):
    nxt[p] = nxt[nxt[p]]

def show_route():
    p = head
    while p != -1:
        print(data[p])
        p = nxt[p]
```

介面：上方是路線圖（站名方格以箭咀相連）；下方是兩行陣列 `data` 及 `nxt`，索引 0–4。學生改 `nxt` 時，路線圖的箭咀即時重畫。走路線時，一架小的士沿箭咀移動，同時陣列中的 `p` 格亮起。

### 4-1　跟住箭咀行（預測）

- 對白：阿 Ken「司機，我講咗三個站，你自己睇住個表行啦。」發哥「唔好由左至右咁讀！跟住 nxt 行！」
- 開始：`data = [中環, 旺角, 尖沙咀, None, None]`，`nxt = [-1, 2, 0, None, None]`，`head = 1`。
- Q1 第一個站？選項：旺角 ✔ ／ 中環（回饋：「中環喺 data\[0\]，但 head 係 1。」）
- Q2 旺角之後去哪裏？選項：尖沙咀 ✔（`nxt[1] = 2`）／ 中環
- Q3 全程次序？答案：旺角 → 尖沙咀 → 中環
- Q4 為何中環是最後一站？選項：`nxt[0] = -1` ✔ ／ 它在 `data[0]` ／ 它是第一個輸入的站

### 4-2　順路經金鐘（操作）

- 對白：阿 Ken「尖沙咀之後，順路經金鐘先去中環！」
- 開始：承接 4-1。空位是索引 3。
- 任務：(1) 設 `data[3] = 金鐘`；(2) 設 `nxt[3] = nxt[2]`（即 0）；(3) 設 `nxt[2] = 3`。學生自己決定先改哪一格。
- 答案：`nxt = [-1, 2, 3, 0, None]`；路線：旺角 → 尖沙咀 → 金鐘 → 中環。
- 陷阱：若先改 `nxt[2] = 3`，再設 `nxt[3] = nxt[2]`，`nxt[3]` 會變成 3，指向自己。動畫：小的士在金鐘不停兜圈，發哥「你搞到佢喺金鐘兜咗十個圈呀！中環嗰段路搵唔返喇！」
- 提示：「先將新站接去舊路線後面，再將舊站指去新站。」

### 4-3　插站程式（排列 + 捉錯）

- 排列：把 `insert_after` 的 4 行排好。
- 捉錯：第 3、4 行對調的版本，用 4-1 的開始狀態執行 `insert_after(2, 3, "金鐘")`。
- Q1 執行後 `nxt[3]` 是？選項：3 ✔ ／ 0 ／ -1
- Q2 結果？選項：路線在金鐘不斷重複，中環不見了 ✔ ／ 正常 ／ 出現運行錯誤

### 4-4　我想先去深水埗（填空）

- Q2 `show_route()` 的輸出？答案：深水埗、旺角、金鐘、中環
- Q3 迴圈執行多少次？選項：4 ✔ ／ 5（回饋：「尖沙咀已經唔喺路線，唔會行到。」）／ 3
- 捉錯：條件寫成 `while nxt[p] != -1:`。追問：輸出少了哪一站？答案：中環（最後一個節點）。

- 「重做」會把題 1、題 2 的操作序列換成另一組（同一結構、不同資料），避免學生背答案。

## 給 Claude Code 的開發備註

把整份文件交給 Claude Code，並要求它依照以下要點開發。

### 技術方向

- 單頁網頁遊戲，以 iPhone Safari 直向畫面為主（寬度 375–430 px），可沿用之前遊戲的 GitHub + Render 做法。
- 只用點按，不用拖放，不彈出鍵盤；所有按鈕高度至少 44 px。
- 程式區用等寬字型及 Python 語法着色；每行不超過約 30 個字元，避免在手機上橫向捲動。
- 中文字型需支援粵語字（嗰、㗎、嘥、攰 等），建議使用系統字型（PingFang HK）。

### 關卡資料與引擎

- 關卡內容（對白、開始狀態、操作、題目、選項、答案、回饋、提示）存成 JSON，一章一個檔案，方便老師之後修改。
- 四種數據結構各寫一個模擬器，邏輯與文件內的 Python 程式完全相同（包括 pop 後舊資料留在陣列、移位後最後一格保留舊值）。動畫及「預測」題的答案都由模擬器計算，不要手寫狀態。
- 寫自動測試：對每一關，用模擬器執行開始狀態及操作，檢查結果等於 JSON 內的答案；一關不符就不可發佈。
- 「捉錯」及「排列」題的錯誤版本，用模擬器執行錯誤程式來播放動畫（例如鏈表無限兜圈時最多顯示 8 步後停止）。
- 選項次序每次隨機排列。
- 考試模式「重做」：題 1、題 2 由引擎產生另一組同結構的操作序列，答案由模擬器計算。

### 進度、解鎖與老師功能

- 進度及星數存在 localStorage；讀寫要用 try/catch，失敗時遊戲仍可玩。
- 老師在控制台為全班或個別學生解鎖全部關卡及考試模式。
- 加入 Google Sheets 成績記錄及老師控制台，見下文「成績記錄」。

#### 老師控制台（網頁，只限老師的 Google 帳戶）

- **全班進度：** 每位學生一行，24 關以顏色格顯示（未玩灰色、1 星黃色、3 星綠色），一眼看到誰未開始。
- **最常錯的題目：** 列出答錯次數最多的 10 題，並顯示最多人選的錯誤選項，方便下一課針對講解。
- **個別學生：** 點姓名看該生每關星數、錯誤紀錄及考試每題得分。
- **篩選：** 按班別、日期範圍篩選。

#### 技術要點

- 用 Google Apps Script 網絡應用程式接收資料並寫入工作表，與之前遊戲做法相同。
- Google 登入用 Google Identity Services（「Sign in with Google」），需要在 Google Cloud 建立一個 OAuth 用戶端 ID，並把遊戲網址（Render）加入允許來源。
- 遊戲把 Google 發出的 ID 權杖 (ID token) 傳到 Apps Script；Apps Script 必須先驗證權杖、取得電郵，才寫入成績，不可直接相信遊戲傳來的電郵。
- 如學校帳戶屬 Google Workspace，管理員有時會封鎖第三方應用程式登入；上線前先用一個學生帳戶在 iPhone 上試登入。
- 沒有網絡時，紀錄先存在手機，有網絡時自動補傳；每筆紀錄附唯一編號，避免重複寫入。
- 學生只能讀取自己的成績，不能看其他同學的資料；老師控制台只允許老師的 Google 帳戶登入（取代老師密碼）。

### 建議開發次序

1. 模擬器 + 自動測試。
2. 一個關卡畫面範本（先做第一章 1-2），在 iPhone 上試玩。
3. 第一章全部關卡，交給幾位學生試玩，收集意見後才做第二至四章。
4. 考試模式及老師功能。
